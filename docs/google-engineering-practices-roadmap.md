# Roadmap for Expanding Google Engineering Practices

This document outlines the action plan to integrate and align the **Agent Starter Kit** with additional engineering best practices, style guides, and development standards from Google.

---

## Objectives
1. **Elevate code quality**: Ensure that the Coder and Reviewer use standards identical to those applied in Google software engineering.
2. **Improve agent-generated documentation**: Align the tone, structure, and clarity of documentation output with Google's technical writing guidelines.
3. **Standardize API and test designs**: Introduce objective criteria for creating robust application programming interfaces and automated tests.

---

## Action Plan

### Phase 1: CL Author Guidelines for Coders
* **Goal**: Guide the developer persona ([personas/coder.md](file:///c:/GitHub/g-agent-starter-kit/personas/coder.md)) on best practices for creating clean, easy-to-review commits/code changes.
* **Actions**:
  * Update the playbook of [coder.md](file:///c:/GitHub/g-agent-starter-kit/personas/coder.md) with guidelines for breaking down tasks into small, self-contained changes (Small CLs).
  * Update [skills/coder-self-review.md](file:///c:/GitHub/g-agent-starter-kit/skills/coder-self-review.md) to require explaining the impact and technical reasoning in commit messages and handoffs.
* **Reference**: [Google CL Author's Guide](https://google.github.io/eng-practices/review/developer/).

### Phase 2: Technical Writing and Style Guide
* **Goal**: Ensure that all markdown files and documentation generated by the agents adopt a professional tone, voice, and structure.
* **Actions**:
  * Expand [rules/edicts/code-style-markdown.md](file:///c:/GitHub/g-agent-starter-kit/rules/edicts/code-style-markdown.md) with style guidelines (active voice, avoiding unnecessary jargon, proper list formatting, and clear usage of technical terms).
* **Reference**: [Google Developer Documentation Style Guide](https://developers.google.com/style).

### Phase 3: API Design Standards
* **Goal**: Standardize REST APIs and data structures created by the agents.
* **Actions**:
  * Create `rules/edicts/api-design.md` containing conventions for resource naming, standard methods (List, Get, Create, Update, Delete), and JSON payloads.
  * Update [personas/architect.md](file:///c:/GitHub/g-agent-starter-kit/personas/architect.md) to consult this edict when designing API changes.
* **Reference**: [Google API Design Guide](https://cloud.google.com/apis/design).

### Phase 4: Software Testing Principles (Testing on the Toilet)
* **Goal**: Ensure the creation of clean, deterministic, and highly maintainable test suites.
* **Actions**:
  * Create `rules/edicts/testing-practices.md` detailing:
    * Use of hermetic tests (no external dependencies/network calls for "Small" tests).
    * Preference for behavior verification over structure verification (avoid mock-heavy tests).
    * Best practices for test readability (understanding DRY vs. DAMP in tests).
* **Reference**: [Google Testing on the Toilet](https://testing.googleblog.com/).

### Phase 5: Resiliency and Production Standards (SRE Patterns)
* **Goal**: Integrate production stability concepts into code quality reviews.
* **Actions**:
  * Update [rules/edicts/code-quality.md](file:///c:/GitHub/g-agent-starter-kit/rules/edicts/code-quality.md) to cover resilient error handling (exponential backoff with jitter on external requests and retries) and structured logging (observability).
* **Reference**: [Site Reliability Engineering (SRE) Books](https://sre.google/books/).

### Phase 6: Front-end and Web Style Guides (HTML/CSS & JS/TS)
* **Goal**: Provide official style guides for web-centric projects.
* **Actions**:
  * Create `rules/edicts/code-style-typescript.md` based on the Google TypeScript Style Guide.
  * Create `rules/edicts/code-style-html-css.md` to ensure semantically clean HTML and structured CSS.
* **References**: 
  * [Google TypeScript Style Guide](https://google.github.io/styleguide/tsguide.html)
  * [Google HTML/CSS Style Guide](https://google.github.io/styleguide/htmlcssguide.html)
