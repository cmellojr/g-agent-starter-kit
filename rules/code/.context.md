## Constraints

- Coders MUST NOT propose or apply a fix before completing a root cause
  investigation.
- Public declarations (modules, classes, functions, methods) MUST have a
  docstring.
- Errors MUST always be logged and never swallowed silently.
- Each fix attempt during debugging MUST be a single, isolated change.
- Database schema modifications MUST be explicitly stated in any handoff or
  commit summary.

## Guidance

- Avoid process-killing constructs during application runtime.
- Treat all external data as untrusted and validate it at the system boundary.
- Reviewers should use the language-specific style guides for quality passes.
