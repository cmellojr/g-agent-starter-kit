Contains edicts, which are authoritative rules and quality standards that govern
code quality, debugging methodologies, and language-specific conventions.

## Summary

- code-debugging.md — systematic debugging methodology, three-strike rule, and
  anti-rationalization list
- code-quality.md — universal code quality conventions (KISS, DRY, SRP, error
  logging, etc.)
- code-style-go.md — Google Go Style Guide rules and conventions
- code-style-markdown.md — Google Markdown Style Guide rules and conventions
- code-style-python.md — Google Python Style Guide rules and conventions
- code-style-rust.md — Rust Style Guide and API guidelines rules and conventions
- code-style-shell.md — Google Shell Style Guide rules and conventions

## Constraints

- Coders MUST NOT propose or apply a fix before completing a root cause
  investigation.
- Public declarations (modules, classes, functions, methods) MUST have a
  docstring.
- Errors MUST always be logged and never swallowed silently.
- Each fix attempt during debugging MUST be a single, isolated change.
- Database schema modifications MUST be explicitly stated in any handoff or
  commit summary.

## Guidance

- Avoid process-killing constructs during application runtime.
- Treat all external data as untrusted and validate it at the system boundary.
- Reviewers should use the language-specific style guides for quality passes.
