Contains reusable skills, procedures, self-review rubrics, and operational
protocols referenced by personas to standardize actions across the framework.
Each skill lives in its own directory as a single SKILL.md.

## Summary

- README.md — schema definition, extraction rules, and directory naming
  standards
- agent-decision/ — structured decision-making and escalation framework for
  ambiguities
- agent-memory/ — cross-session long-term and session memory management
- architect-design-tree/ — builds the grill's design tree of decisions and
  dependencies
- architect-impl-grounding/ — grounds grill artifacts in the codebase per epic
- boot/ — initialization sequence covering updates, memory, and environment
  setup
- browser-inspect/ — browser inspection for verifying rendered web UI
- code-coherence-review/ — logic correctness, integrity, and structural checks
- code-design-review/ — code design, simplicity, and maintainability checks
- code-documentation-review/ — documentation and technical writing verification
  checks
- code-quality-review/ — style, syntax, and rules compliance review procedure
- code-sec-review/ — security review methodology aligned with CWE/OWASP
- coder-self-review/ — implementation self-review gate for code changes
- context-maintenance/ — schemas and guidelines for context files and the
  feature map
- contextualizer-self-review/ — TRACE rubric for evaluating context file scans
- dispatch/ — prompt assembly and routing guidelines for persona models
- grill/ — interview protocol over the Architect's design tree
- loop-recovery/ — retry loop detection and recovery escalation procedures
- plan-management/ — plan lifecycle from grill entry to per-epic execution
- review-loop/ — two-mode review loop for epics and full branches
- reviewer-architect-adversarial/ — adversarial review and assumption attacks on
  grill artifacts
- reviewer-handoff/ — verdict guidelines and final output format for reviewers
- reviewer-self-review/ — SHIELD quality gate rubric for reviewer output
- task-tracking/ — file-based task management for multi-step workflows
- web-search/ — web search and page fetch through the TinyFish CLI
- assets/ — directory containing helper scripts and their companion tests

## Constraints

- Skill directories MUST follow the schema defined in skills/README.md.
- Skill directory names MUST be lowercase, hyphenated, and match the `name`
  frontmatter field.
- Each skill directory MUST hold exactly one SKILL.md.
- Procedures MUST be procedural; declarative constraints belong in rules/.
